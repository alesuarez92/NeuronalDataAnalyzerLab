# NeuroAnalyzer support website

Static site (HTML, CSS, one JavaScript file) for the NeuroAnalyzer MATLAB
toolbox. There is no build step and no external JavaScript; fonts come from
Google Fonts. All links are relative, so the folder works from any static
host and when opened directly from disk (`file://`).

## Layout

| Path | Contents |
| --- | --- |
| `*.html` | One file per page: `index`, `install`, `ldf`, `ephys`, `imaging`, `features`, `batch`, `sessions`, `guide`, `formats`, `demo-data`, `validation`, `references`, `about`, `404` |
| `assets/site.css` | Design system (IBM Plex, the toolbox's UITheme colours, light and dark themes) |
| `assets/site.js` | Header, navigation, footer, the "synthetic demo data" strip, theme switch and the walkthrough player. The walkthrough frames and captions are listed in `TOURS` at the top of the file; a page shows one with `<div data-tour="ldf"></div>` |
| `assets/frames/` | Window screenshots taken by the CI walkthrough tests (`tests/*WalkthroughTest.m`) on demo data |
| `assets/figures/` | Explanatory figures from `docs/`, drawn by the author |
| `assets/favicon.svg` | Tab icon |

Every screenshot that shows analysis results carries the badge
"DEMO DATA — synthetic, generated by core/DemoData.m" (or the `core/demo/`
generator that made it).

## Deploy on Cloudflare Pages

1. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git**, and choose this repository.
2. Build settings:
   - **Framework preset:** None
   - **Build command:** leave empty (none)
   - **Build output directory:** `website`
   - **Production branch:** `main`
3. Save and deploy. Cloudflare serves `404.html` for missing paths
   automatically.

Alternatively, without Git integration: `npx wrangler pages deploy website`.

## Deploy on GitHub Pages

GitHub Pages publishes from the repository root or `/docs`, not from
`website/`, so use a workflow:

1. Repository **Settings → Pages → Source: GitHub Actions**.
2. Add a workflow that uploads the folder, for example:

   ```yaml
   name: Pages
   on: { push: { branches: [main], paths: ['website/**'] }, workflow_dispatch: {} }
   permissions: { contents: read, pages: write, id-token: write }
   jobs:
     deploy:
       runs-on: ubuntu-latest
       environment: { name: github-pages }
       steps:
         - uses: actions/checkout@v4
         - uses: actions/upload-pages-artifact@v3
           with: { path: website }
         - uses: actions/deploy-pages@v4
   ```

On a project site (`https://<user>.github.io/<repo>/`) every page works, but
`404.html` sets `<base href="/">` so that its links resolve from any missing
path; change that to `/<repo>/` in `404.html` for a project site.

## Preview locally

Open `index.html` in a browser, or serve the folder:

```sh
python3 -m http.server --directory website 8000
```

## Updating

- **Screenshots:** download the `window-screenshots` artifact of a CI run
  (Actions tab, kept 7 days). Copy the ones the pages use into `assets/frames/` and optimise them
  **losslessly only** (`optipng -o5 -strip all`; never `pngquant` or other
  lossy tools). A frame named in `site.js` or a page must exist in
  `assets/frames/`.
- **Text:** the guide, the demo expectations and the inputs/outputs are
  taken from the Help topics in `apps/HelpApp.m`. When Help changes, update
  the matching page.
- **References:** add an entry to `references.html` only after checking
  authors, year, title, venue and DOI against PubMed or the publisher, and
  link to it from pages as `references.html#ref-<key>`.
- Growth ideas belong in `ROADMAP.md`, not on the site.
